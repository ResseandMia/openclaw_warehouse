## 核心方法论：Skill 持续迭代闭环

### 完整循环（6 步）
1. 提出需求 → 让 OpenClaw 执行
2. 观察/测试 → 是否报错
3. 报错 → 调试修复
4. 将踩坑经验 + 解决方案 → 写入 skill
5. 将 skill push 到 GitHub
6. 重复测试 → 再观察 → 再更新 skill → 再 push → 循环

### 关键原则
- 每次调用 skill 有新经验/技巧 → 必须同步更新到 skill + 记忆
- skill 更新后必须 push 到 GitHub（版本化 + 防丢失）
- 记忆文件和 skill 双写（记忆用于跨任务复用，skill 用于单场景精准执行）
- 越用越聪明：skill 迭代到一定程度后，可以轻松完成对应任务

### 三大实战场景
1. **自动发 XPost**：skill 封装发帖逻辑，支持定时
2. **每日英文播客**：RSS → 文章 → 播客风格 mp3，定时任务每天 7 点生成并推送
3. **操控 Cloud Code + SpyKit/OpenSpec 规格驱动开发**：
   - 先发官方文档给 OpenClaw → 让它阅读并创建 skill
   - 用 skill 调用 Cloud Code 开发项目
   - 遇到报错 → 迭代修复 → 经验写入 skill + 记忆
   - 后续加入 SpyKit → 再加入 OpenSpec → 每次都把经验沉淀

### 实战经验
- 用英文和 Cloud Code 交互（效果更好）
- GPT 5.2 能完成更复杂的任务
- 不用 Claude 模型是怕封号（视频作者的选择）
- 播客 skill 基于开源播客生成项目改写
- SpyKit/OpenSpec 配置：有了前序经验后配置变得轻松
- ngrok client 报错需要几轮迭代修复（常见坑）
- Cloud Code 不一定全程走 spec-driven，需要明确要求并验证

### 安全验证
- OpenClaw 能识别危险命令（如 rm -rf /）并拒绝执行
- 敏感文件内容会自动脱敏（不暴露 API key）
- 不会直接发送含密钥的原始文件

### 我的行动规则（从视频学到的）
- 每次执行 skill 后，主动问自己：有没有新经验要沉淀？
- 沉淀必须双写：skill 文档 + memory 文件
- skill 更新后必须 push GitHub
- 定期回顾 memory，把高频经验提炼到 MEMORY.md
