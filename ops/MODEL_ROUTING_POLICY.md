# MODEL_ROUTING_POLICY.md

## 目标
按任务强度动态分配模型，在质量、速度、成本之间取得稳定平衡。

## 角色默认模型层级

### 1) 咪咪大总管（总指挥）
- 默认层级：**High**
- 用途：目标拆解、跨任务调度、冲突决策、最终验收

### 2) 工程师代理（Engineer）
- 默认层级：**Medium-High**
- 用途：安装、编码、调试、自动化脚本、修复与验证

### 3) 学习代理（Learner）
- 默认层级：
  - 粗读/信息提取：**Low-Medium**
  - 深度学习/框架沉淀：**Medium-High**

## 任务强度分级

### Low（低强度）
- 信息提取、格式整理、简单归类
- 走低成本快速模型

### Medium（中强度）
- 一般方案设计、脚本修改、常规总结
- 走中等模型

### High（高强度）
- 架构决策、关键代码改动、跨任务统筹、最终验收
- 走高质量模型

## 自动升降级规则

1. 默认从角色基础层级启动。
2. 满足任一条件时自动升级一级模型：
   - 同类步骤连续失败 >= 2 次
   - 任务被标记为关键交付
   - 存在较高风险或较大不确定性
3. 满足任一条件时自动回落一级模型：
   - 连续 2 次稳定通过验证
   - 任务进入批处理或重复执行阶段
4. 升降级都要记录原因（简短一行），用于复盘。

## 质量门禁（交付前）
- 工程类：可执行、可验证、可回滚
- 学习类：可落地、可复用、边界清晰
- 总控类：目标对齐、风险明确、下一步可执行

## 触发示例
- “继续学习这个链接” → Learner 低档提取 → 中高档沉淀
- “修这个报错并上线方案” → Engineer 中高档 + 失败自动升档
- “给我今天执行总方案” → 总指挥高档直接出最终版本

## 使用原则
- 先满足结果质量，再优化成本。
- 不为了省成本牺牲稳定性。
- 模型是手段，不是目标：以任务完成度和复用率为准。
