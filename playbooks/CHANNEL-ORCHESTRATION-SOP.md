# CHANNEL-ORCHESTRATION-SOP.md

## 目标
建立“总调度派发 + 子代理分频道执行 + 标准交付/求助”的固定流程，避免上下文污染与反复纠错。

## 角色与频道模型
- 总调度（咪咪大总管）：
  - 接收任务频道：`#inbox`（你给任务）
  - 调度频道：`#dispatch`
  - 汇总回报频道：`#delivery`
- 工程师代理：
  - 执行频道：`#exec-engineer`
- 学习代理：
  - 执行频道：`#exec-learner`

> 实际频道名可按你的 Discord 现有结构替换，但职责不变。

## 标准流程（固定）
1. 你在 `#inbox` 给任务。
2. 总调度在 `#dispatch` 输出：任务拆解、分配对象、验收标准、截止时间。
3. 子代理只在各自 `#exec-*` 频道执行，禁止跨频道混聊。
4. 子代理按固定交付模板回报到 `#dispatch`。
5. 总调度统一验收后，在 `#delivery` 给你最终结果。

## 子代理交付模板（必须使用）
```text
[任务交付]
- 任务ID:
- 执行代理:
- 状态: 成功 | 部分成功 | 失败
- 已完成:
- 产出位置: (文件/链接/提交)
- 验证结果: (通过/未通过 + 依据)
- 风险与边界:
- 需要总调度协助:
- 下一步建议:
```

## 子代理请求协助模板（必须使用）
```text
[请求协助]
- 任务ID:
- 当前卡点:
- 已尝试:
- 失败信息/日志:
- 需要的帮助类型: 决策 | 资源 | 权限 | 技术支持
- 建议备选路径:
```

## 提醒机制（默认）
- 子代理出现以下情况必须立即提醒总调度：
  1) 连续失败 >= 2 次
  2) 缺权限/缺凭据
  3) 验收无法通过
- 总调度收到提醒后必须在同一任务中给出：
  - 决策
  - 调整方案
  - 是否升级模型/改派代理

## 防污染规则
1. 执行上下文只在各自 `#exec-*` 频道维护。
2. 汇总信息才进入 `#dispatch` / `#delivery`。
3. 禁止将私聊敏感信息写入群聊执行频道。
4. 需要共享的稳定经验，写入 `ops/` 或 `playbooks/`，不写在临时聊天里。

## 验收与收口
- 总调度验收标准：可执行、可验证、可回滚。
- 未达标：退回对应执行频道返工。
- 达标：在 `#delivery` 一次性收口，给“已完成/进行中/风险/下一步”。

## 变更规则
- 频道、模板、阈值调整后，必须更新本文件并提交仓库。
